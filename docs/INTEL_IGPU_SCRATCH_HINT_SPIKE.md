# I19 S1.5 scratch and hint probe preparation

Status: source and runner compile on DPC++ 2025.3.3. Correctness smoke runs at 257 and 65,536 elements passed for `shared`, `device`, and `shared_prefetch`; `shared_advice` reported unsupported without a verified advice code. Raw logs and manifests are in `out/intel-review/scratch-hint/20260923-190511-528/` and `20260923-190342-617/`. These sequential smoke runs are not a controlled performance comparison. This bounded standalone probe cannot establish full-model capacity, mapped-file import, residency, or a production allocation policy.

`benchmarks/intel/memory/scratch_hint.cpp` executes one arm per process: `shared`, `device`, `shared_prefetch`, or `shared_advice`. All arms allocate a reusable `uint32_t` scratch range and host check buffer before samples. The GPU kernel overwrites every scratch element with a trial-specific deterministic value. Each sample waits for kernel completion, copies the whole result to host, and verifies every element. No CPU/GPU concurrent access or initial scratch contents are assumed.

The raw output is `sub0.intel.scratch-hint-raw.v1`: `key=value` metadata followed by one `cold` and seven numbered `warm` CSV samples for a passing selected arm. This follows I21's raw-output conventions but is **not** accepted by the prepared-copy-specific I21 parser or its result schema. The runner retains each process log, hash and build identity in `out/intel-review/scratch-hint/<UTC>/`. It performs no pairwise inference or eligibility claim. A later I21 adapter and independent-process alternating schedule are required before a comparison can be promoted.

All times use host `std::chrono::steady_clock` and include asynchronous completion. `hint_ms` starts immediately before `queue.prefetch` or `queue.mem_advise` submission and ends after `wait_and_throw`; it is zero for unhinted arms. `kernel_ms` covers submit through completion. `readback_ms` covers `queue.memcpy` through completion. `validation_ms` covers every-element host verification. `validation_inclusive_ms` begins before any hint and ends after verification. Allocation, queue/device creation, build, process launch, and output formatting are outside these boundaries. The GPU work is write-only, so prefetch is deliberately a control of questionable value rather than a recommendation.

The installed 2025.3 `sycl/queue.hpp` declares both APIs. `prefetch` accepts a USM pointer and byte count; a successful return proves the API call completed, not that any pages migrated. `mem_advise` takes a device-defined integer and the inspected headers provide no portable named advice value. Accordingly `shared_advice` reports `status=unsupported` unless an independently verified code is supplied through `-AdviceCode`; even acceptance of such a code would not prove the hint had an effect. Missing required USM aspects and rejected hint calls are explicit unsupported outcomes. A mismatch or other execution error is a failure.

The runner's `-CompileOnly` path builds and records identities without selecting a GPU or running the executable. The first correctness gate has passed at two bounded sizes. A performance comparison still needs an uncontended hardware window, independently alternating process samples and I21 integration. Any device-specific advice code must be audited on this exact runtime before enabling that arm.
