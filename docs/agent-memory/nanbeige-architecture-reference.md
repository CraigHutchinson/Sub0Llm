## Design-tension flags (from the earlier Nanbeige4.1 architecture summary, Sebastian Raschka's writeup)

- **QK-norm**: Sub0Llm ships this (`qk-norm.md` memory -- DONE, CPU+CUDA, per-head RMSNorm on Q/K before RoPE). Nanbeige4.1 explicitly DROPPED it, citing interference with long-context capability. A live, contested design choice in the field, not settled either way -- **flag for follow-up if Sub0Llm's own context length is ever pushed**: watch for the same interference pattern.
- **Embedding tying**: Sub0Llm ships tied embeddings (`weight-tying-tied-embeddings.md`). Nanbeige4.1 deliberately untied theirs "for training performance despite higher parameter counts" at 3B scale -- different regime than Sub0Llm's toy configs, not directly transferable, but the same trade-off exists if Sub0Llm ever scales up.
- **RoPE context extension via ABF** (Adjusting Base Frequency): Nanbeige4-3B extends to 64K context this way. Sub0Llm already uses RoPE (`ROPE_THETA`) but has no documented ABF-style extension mechanism -- worth a look if context-length scaling becomes a goal.

## Three verified Nanbeige4.5-staged techniques (real source, `modeling_nanbeige.py`)

### 1. Concatenated n-gram embeddings (`NanbeigeNgramEmbedding` + `NanbeigeNgramLayerFusion`) -- DIRECTLY relevant to [[scratch-tokens-context-translation-layer]]

For each token, computes ADDITIONAL features from rolling POLYNOMIAL-HASH n-grams (bigram..n-gram, `k` separate hash tables per n-gram order, hashed into small prime-sized vocab tables -- avoids an explosion of unique n-gram embeddings, fastText-char-n-gram-style but over TOKEN n-grams). Two fusion modes: `"average"` (per-table small embeddings, each linearly projected up and summed) or **`"concat"`**: every n-gram table's embedding (each `hidden_size/num_embedders` wide) is literally concatenated end-to-end with NO interference between tables, then passed through ONE learned linear (`concat_proj`) down to `hidden_size`. **This is exactly the "concat-then-learn-project" compression operator floated as an untried candidate for Sub0Llm's own axis-9 bottleneck (a real lab has a working, shipping implementation of it)** -- concrete reference for a future spike, not just a hypothesis anymore.

The bigger idea, genuinely new to this investigation: **`NanbeigeNgramLayerFusion` re-injects the n-gram signal at MULTIPLE layers**, not once at the input embedding -- a sigmoid-GATED additive residual (`gate = sigmoid(<normed_hidden, normed_ngram_key>/sqrt(d))`, `hidden = hidden + gate * value_proj(ngram_embed)`) applied at several configured depths (`ngram_layer_downproject_size`, per-layer dict of fusion modules). This directly targets exactly what Sub0Llm's Phase G/H found: candidate 1/mechanism A inject a packed representation ONCE before layer 1 and let ordinary computation carry it forward (which candidate 2 proved loses fidelity vs. real per-layer computation); Nanbeige's per-layer gated re-injection is a genuinely different, untried middle ground -- keep the O(1) single-position cost, but don't rely on ONE injection surviving N_LAYERS of dilution; **top candidate for the next axis-9 spike**, more promising than concat-alone since it also addresses the "one shot before layer 1 isn't enough" finding directly.

Also has `NgramCache` (extends `DynamicCache`) carrying rolling n-gram context correctly across autoregressive DECODE steps -- relevant to the earlier prefill-vs-decode compute discussion.

### 2. mHC = Manifold-Constrained Hyper-Connections (`NanbeigeHyperConnectionModule`) -- general architecture modernization, not scratch-token-specific

Originates from a **DeepSeek** paper (late Dec 2025), not Nanbeige's own invention -- Nanbeige adopted it. Generalizes the single residual stream into `n` parallel streams. Each layer learns `h_pre` (how to aggregate the n streams down to this layer's actual input), `h_post` (how to broadcast this layer's output back across the n streams), and `h_res` (an n×n matrix mixing the streams layer-to-layer). The "manifold-constrained" part: `h_res`, when not fixed to identity, is projected via a genuinely elegant custom **Sinkhorn-Knopp** autograd Function (differentiable iterative row/column normalization) onto (an approximation of) the doubly-stochastic-matrix manifold -- keeps the residual-mixing matrix well-conditioned across many layers, addressing training instability/scale limits. Initialization is deliberately near-identity (bias terms push sigmoids to ~0/~1 so it starts equivalent to an ordinary single-stream transformer and learns to deviate) -- low-risk incremental adoption path, not a from-scratch architecture change. No direct Sub0Llm relevance found yet; flagged as a real, shipping, general-purpose training-stability technique worth knowing about if Sub0Llm ever pushes depth/scale further.

### 3. LoopSplit + depth attention -- conceptually adjacent to the KV-trace work, different axis

**LoopSplit** (`enable_double_loop_split`, `_get_double_loop_split_layer_order*`): splits `num_hidden_layers` into an un-looped first block, a MIDDLE block that gets weight-shared-REPEATED several times, and an un-looped final block -- a refinement on "Looped Transformers" (weight-tied iterative depth, real established research area) that only loops the middle "reasoning core" rather than the whole stack, keeping early feature-extraction and late output layers single-pass.

**Depth attention** (`_apply_depth_attention`, `_depth_attention_mix_value`): at layers where `layer_idx % depth_attention_stride == 0`, that layer's own (K,V) gets cached into a list that persists ACROSS LAYERS (depth), not across sequence position. Later layers then run a genuine softmax-attention mix (query vs. all cached earlier-DEPTH keys, weighting the values) to pull information from specific earlier LAYERS, not just the immediately-preceding one -- literally "attention across the depth dimension," DenseNet-style skip connections implemented as real attention instead of a fixed additive skip. Conceptually adjacent to Sub0Llm's KV-trace memoization (both cache and reuse real K/V rather than approximating), but on a completely different axis -- depth-reuse-within-one-forward-pass vs. Sub0Llm's cross-mention/cross-context reuse. Not directly applicable, but worth knowing this "cache K/V across a different axis and attend over it" pattern has real precedent beyond the sequence dimension.
