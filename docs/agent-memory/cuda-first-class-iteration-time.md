User guidance (2026-06-20): **CUDA should be a first-class goal for ITERATION TIME.** Our diffusion training/sampling (ch29/ch30, sub0diff) runs CPU-only (8 P-cores, ~50-100 win/s) — every experiment waits minutes-to-hours; GPU would slash that.

**Why:** the whole tokenization/decode/hierarchy investigation was gated by slow CPU runs. Faster iteration = more experiments = faster progress. (Also recall diffusion is GPU-FAVORABLE: a denoising step is a full-canvas forward ≈ prefill, compute-bound — see [[diffusiongemma-reference-run]] ~14x GPU; unlike AR decode which was PCIe-bound.)

**How to apply:** note it now; **take quick CUDA wins opportunistically when they fit the current work** (don't drop everything to build CUDA, but when a hot path is being touched, prefer adding/using the CUDA path). The main engine already has CUDA scaffolding ([[cuda-build-setup]], [[ch27-gpu-forward-build-arc]] — RTX 5070 8GB sm_120, CUDA 13.2, cuda preset).

**DONE 2026-06-21 (the BIG GPU-training lever, commit c00b66c): CUDA CACHING ALLOCATOR.** Profiling `ch29 --device cuda` found GPU training was **malloc-bound, not compute-bound** — every Tensor did a synchronising `cudaMalloc` + `cudaFree` (backend.cpp `alloc()`), and a transformer step allocates hundreds of short-lived intermediates → ~5 s/step at word-level vocab (orders of magnitude over the kernel ceiling). Fix: a size-keyed caching pool (`CudaPool` in backend.cpp; freed blocks → free-list, reused instead of released; `Storage::free_fn` returns the block). Training shapes repeat every step → steady-state cudaMalloc→0. Recycled blocks are safe (written before read: zeros() memsets, every op overwrites its output). **Controlled bench: GPU 0.0635 → 0.0158 s/step (4×; 23.9× vs CPU)**, all CUDA parity tests + gradcheck still green. **Lesson: on this engine the per-op allocator was a BIGGER GPU lever than cuBLAS** — measure before optimizing kernels. Remaining cuda LOW: GPU recall/recovery probes (so the post-training sweep needn't fall back to CPU); #5 wce multi-block; possible pool cap. This made the ch32 hierarchy P-phases cheap to iterate ([[ch31-diffusion-optimization-sandbox-plan]]); P1 codec (1a/1b) already built + tested on it.

Always isolate the thing you're timing (the controlled `[bench]` step test was the trustworthy number); wall/steps with a big fixed tail is meaningless.
