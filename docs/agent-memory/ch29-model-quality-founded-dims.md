The Ch29 diffusion denoiser eval is weak because the model is **underfit AND mis-proportioned** (not a data problem — completeb corpus is 2.19M tokens, seen ~80× over 684K steps, plateaued). Baseline (D=128, L8, 8/4 heads, d_ff=384, step 684640): recall 33%/27%/17%/8% at 10/25/50/75% noise, NELBO 4.19, edges ~half of interior.

**Founded reference proportions (researched, embed in arch choices):**
- paulseet/tiny_llm: D=96, L3, H3 → head_dim **32**, d_ff=**4·D**=384, block 64, 354K params (char, 1.1M corpus).
- nanoGPT char (Karpathy): D=384, L6, H6 → head_dim **64**, d_ff=**4·D**=1536, block 256, 10.6M, dropout 0.2, lr 1e-3.
- RULE: head_dim ≥ 32 (64 typical); d_ff = 4·D; balance depth↔width (more D ⇒ more layers, not the reverse).
- Our completeb (D=128, L8, H8 → head_dim **16**, d_ff **3·D**) violates all three: too deep+narrow, heads too small, FFN too thin.

**Embedded in code (ch29 main.cpp, validated, rebuilds after the running job):** `--founded` preset (D=256, L6, H8→head_dim 32, d_ff=1024=4·D, ~5-6M params); CLI arch flags `--embed-dim/--n-layers/--n-heads/--n-kv-heads/--d-ff` (no recompile for capacity experiments); runtime sanity warnings (head_dim<32, d_ff<4·D, deep+narrow); cited Config docs. Also BPE caching (load saved tokenizer, skip ~110s retrain on resume/eval).

**Curriculum ([[ch28-curriculum-findings]] revived as reusable `sub0diff::train::NoiseCurriculum`, `--curriculum`):** frontier-point + token-gated ceiling. VERIFIED on the real corpus it does NOT skip to high noise — ramps gradually and self-corrects (0.05→0.10→0.15→drops to 0.05 on regression→0.10→0.20), unlike a tiny corpus which races. Ramp rate tunable via `--curriculum-min-tokens` (default 1500). Pool path: `ParallelTrainer::set_t_range` (atomic) lets the master drive the dynamic ceiling.

**Curriculum run RESULT + bug (key lesson):** frontier-point `--curriculum` at D=128 HURT (recall 8.9% vs 15.4%, NELBO 4.82 vs 4.19) — but because of a bug, not the idea. It early-stopped at 51K steps (baseline ran 684K) when the held-out NELBO went 4.82→5.8 (worse). Cause: frontier-POINT trains at EXACTLY the ceiling, so once converged at ceiling=1.0 it trained ONLY t=1.0 (fully masked, zero context) — degenerate — wrecking the easy regime the UNIFORM-noise eval measures → NELBO climbed → premature stop. Lesson: **a uniform-noise eval/early-stop is INCOHERENT with a non-uniform (point) curriculum.** FIX applied: during the ramp keep frontier-point (Ch28's mastery detection), but once the ceiling CONVERGES switch to the full band [0.02, ceiling] = the formal objective (no t=1.0 degeneracy, coherent eval, no premature stop). The curriculum becomes an easy-first WARMUP then the formal objective. Needs a re-run to validate.

**Eval-cadence / schedule (tech-debt fix, tested):** extracted `sub0diff::train::make_schedule` (`schedule.hpp`, 9 unit tests) — ONE place derives eval cadence, safety bound, eval sample sizes. Fixes a print bug (eval cadence was printed PRE-÷threads: said 17116 steps, actual 4279) and ENFORCES the Ch28 coverage rule: ≥50% epoch (non-overlapping windows) trained between evals (ceil so it's never just under), thread count folded in once. Verified completeb already had ~50% coverage; reports `coverage_per_eval`. `--eval-factor 1.0` gives full-epoch evals.

**A/B RESULT — founded char-AR priors DO NOT transfer to BPE-diffusion (empirical, trumps the priors):** fast small-corpus A/B (136K tokens, min-epochs floor) at constant D=128: baseline (8 heads/8 layers, head_dim 16, d_ff 3×) got **14.8% recall, NELBO 4.38**; the "founded-fixed" shape (4 heads/6 layers, head_dim 32, d_ff 4×) got **3.9% (near the unigram floor), NELBO 5.52**. So for THIS bidirectional-diffusion BPE model, MORE heads + MORE depth beat bigger-head_dim + fewer-layers. The `--founded` preset and the "head_dim<32" warning are char-level-AUTOREGRESSIVE references, NOT laws here — treat as advisory. (Verify B's magnitude isn't a 4-head/2-kv pathology before fully trusting −11pts.)

**CAPACITY-BOUND, not data-bound (key):** baseline on 136K-token subset (14.8%) ≈ baseline on full 2.19M (15.4%) — 16× more data gave ~nothing. The model is at its ARCHITECTURE capacity ceiling (~15%). More data won't break it; more capacity (WIDTH while KEEPING the baseline's many-heads/many-layers shape) will. Next clean test: D=192/256 with L8 + 8 heads (head_dim 24/32) + n_kv_heads 4 + d_ff (3-4×), on the full corpus (capacity-bound), + dropout if it overfits.

**CAPACITY HYPOTHESIS REFUTED — wider is WORSE + fragile (measured):** scaling D=128→192 (same 8h/8L shape) on the 136K-token proxy: seed=42 got STUCK in the unigram basin (NELBO 5.5, recall 3.9%); seed=7 escaped but only to NELBO 4.88 / recall 8.8% — still WORSE than the baseline D=128 (NELBO 4.38, recall 14.8%). So wider models here are (a) seed-fragile (often can't leave the unigram basin from scratch on CPU) AND (b) reach a worse solution even when they train. LR warmup+cosine did NOT rescue them and HURT the baseline (12.0% vs 14.8% — decayed it into an earlier early-stop), so warmup is now OPT-IN (`--warmup-steps`, default constant LR). **Conclusion: the architecture lever within this family is EXHAUSTED — baseline D=128/L8/8h (~15%) is the practical ceiling; scaling width/re-proportioning makes it worse.** ~15% appears inherent to this regime (small, from-scratch, CPU, 2.19M tokens, bidirectional BPE diffusion). Remaining orthogonal levers (unverified, none a sure win): longer context (seq_len 64→128), curriculum-as-warmup (the converged→band fix, untested at scale), better/more-diverse data, a different objective. Added flags: `--lr/--warmup-steps/--seed/--min-epochs` + `Adam::set_lr`.

**CONTEXT (seq_len) helps then SATURATES at the block size (measured):** recall 16→6.8%, 32→9.2%, 64→14.8%, 128→16.4% (gains +2.4,+5.6,+1.6) — climbs steeply to ~64 then flattens. Corpus lines ≈8 tokens, blank-line blocks ≈52; the model captures within-coherent-unit context by ~64 and cross-block context adds ~nothing at 3×+ the O(T²) cost. **seq_len=64 ≈ optimal; longer context is NOT a lever.** The "coherent windows" hypothesis reframed: the win is longer windows holding more COMPLETE lines, achieved already at 64. Train tracks held-out at every seq_len (still underfitting). Added `--eval-train` (train-stream recall), `--min-epochs` floor (default 20; a small-corpus run early-stopped at ~4 epochs → unigram collapse → two archs gave IDENTICAL recall = invalid A/B). Full axes map documented in `diffusion/chapters/ch29_diffusion_training/README.md` (axes A–K). Remaining untested levers: whole-word masking + word-level recall metric (axes H/I — most promising now), optimization fragility (axis F — to fit bigger), block-separator token (axis D).

**WHAT THE 15% MEANS — it's HONEST, the gap is CONTENT PREDICTION (measured, axes H/I):** added a word-START/continuation recall split + word-level recall (tokenizer-agnostic `is_word_start` Ġ-marker table), whole-word masking/corruption (`--whole-word`, in training AND eval), per-sample dump (`--inspect N`), and periodic in-training recall (`--track-recall`). All shared/reusable in `recovery.hpp`/`.cpp` + `noise_schedule.hpp` + `diffusion_loss.hpp` + `parallel.hpp`; 2 new unit tests pass. completeb baseline breakdown: token **15.4%**, word-level **14.1%** (≈token → NOT a metric artifact), word-START **11.4%** (predict a word from context — the honest hard target), continuation **17.8%** (complete a partial word — easy; only 1.56× easier). `--inspect` per-sample dumps show the MECHANISM: the model reliably recovers punctuation, subword completions, and high-freq function words (·he/·and/·my), but on content word-STARTS it falls back to a frequency prior (substitutes ·the/·of/·and/·that for the real, often rarer word); 0%-recall windows are dense-masking or proper-noun/poetry passages where context is destroyed. **Conclusion: the model learned the easy structure, not content prediction — mechanistic confirmation of the underfit ceiling.** Whole-word masking makes the task honest (~11-14%) but won't unlock hidden capability. WHOLE-WORD-TRAINING A/B — **REFUTED as a lever** (proxy V=512, identical deterministic BPE → 71094 word targets both sides): on the identical honest whole-word eval, whole-word-TRAINED = word-START 3.8% / word-level 1.8%; per-token-TRAINED evaluated under whole-word = word-START 3.7% / word-level 2.5% (TIED, per-token slightly better on word-level). Fully-converged (24k-step) per-token also 3.7% → ~3.8% is the genuine whole-word ceiling, not undertraining. **Masking strategy is NOT a lever; the hard ceiling is content prediction (~4% whole words), unchanged by how we mask.** The per-token 15% = ~⅔ completion (continuation 17.4%) over ~4% true word prediction. RESOLVED both: (a) UNDERTRAINING test — **MILDLY UNDERTRAINED (corrected; an early 3-reading "flat" call was premature)**: resuming completeb past early-stop (`--track-recall`) showed recall SLOWLY CLIMB over the longer horizon — 21.4%→22.8% on the {0.25,0.50} monitor (START 16.1%→17.6%), NELBO 4.29→4.20, over ~110K extra steps (~32 epochs). Real but sub-threshold gains (below early-stop's min_improvement=0.01), so the stop was slightly premature with steeply diminishing returns. KEY IMPLICATION: the model is **optimization-limited, not at a hard capacity wall** → motivates the optimizer lever (Muon, [[optimizer-alternatives-backlog]]). LESSON: judge a recall trend over a LONG horizon (≥tens of epochs), not 3 within-noise readings. (b) VOCAB-SIZE sweep — **smaller vocab wins, budget-matched**: V=512/1024/2048 at a FIXED 40k steps (early-stop off) gave word-level **13.6% / 8.1% / 5.2%**, NELBO 4.13/5.04/6.01 — smaller wins DECISIVELY; mechanism = data-sparsity (bigger vocab → rarer tokens → harder to fit on 136K proxy tokens), NOT over-fragmentation. The over-fragmentation hypothesis (single-char word-starts ·f/·st/·com at V=512) is REFUTED as a bottleneck. IMPORTANT methodology lesson [[ch29-training-methodology-backlog]]: the NAIVE (self-terminating) vocab sweep was MISLEADING — bigger vocab early-stopped sooner (24030/15515/6222 steps), so V=2048 read 1.1% purely from undertraining; budget-matched it's 5.2% (5×). CAVEAT: proxy (136K tok) penalizes large vocab; full-corpus optimal could be >512 (definitive full-corpus budget-matched sweep ~10h, low-priority). With masking/context/arch/coverage/early-stop/vocab all characterized, the ONE promising untested lever is the OPTIMIZER (Muon, [[optimizer-alternatives-backlog]], axis F).
