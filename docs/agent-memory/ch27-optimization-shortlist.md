The deep-research workflow (Jun 2026) on "novel cross-discipline CPU LLM inference optimizations" was crippled twice by session-limit 429s: only 4 of ~24 sources survived, all on LOSSY angles (HQQ, QuIP#, PowerInfer, sparse-finetuning). The angles that matter for us — better int8 GEMM kernels (PP), speculative decoding (TG), entropy-coded weights/scheduling — got zero surviving sources. Synthesized manually instead.

KEY FILTER: our hard gate is byte-exact greedy parity vs llama.cpp Q8_0. Every research "confirmed" finding (sub-8-bit quant, sparsity, PowerInfer, BitNet, LUT mpGEMM at low bits, early-exit) is LOSSY → changes logits → DISQUALIFIED from the main track. They belong only to a hypothetical separate "fast, non-parity" mode.

Prioritized PARITY-SAFE levers (the real shortlist):
0. **Multi-thread PP scaling** — DONE (Jun 2026). The single-thread kernel win exposed an Amdahl wall: forward_prefill ran transpose_mt, quantize_rows, embed, the per-token rmsnorm+residual loops and gelu⊙up SERIALLY on the caller while 15 workers idled (win single-thread / lose multi-thread = the tell). Parallelized all of them via parallel_for over the token dim (bitwise-identical, independent rows; transpose parallel over T not M to avoid false sharing). RESULT: default(~16t) PP 23.06 → 29.14 tok/s (+27%); now BEATS llama at the operating point too (29.14 vs 25.95). 1→16 scaling 6.4×→7.5×. Greedy byte-identical to llama. NOTE: -t 24 (8P+16E) is SLOWER than -t 16 — the 16 E-cores oversubscribe the spin-barrier; 16 threads is the PP sweet spot. Pool already does dynamic work-stealing (next_.fetch_add), so the gap was serial Amdahl, not load imbalance.
1. **Prefill int8 GEMM tiling** — DONE (Jun 2026). NC=4→NC=8 column blocking + hoisting the activation f16→f32 scale decode out of the per-row inner loop (decode_q8_block_scales once per matmul, gemm_row_q8_0 xsd overload). +15-21% single-thread kernel, bitwise-identical (test asserts ==). RESULT: single-thread on the real model now BEATS llama b9334: PP 3.62 vs 3.28 tok/s, TG 1.38 vs 1.19 tok/s, greedy byte-identical. The user's "1.9 vs 4.41 single-thread" was STALE (commit ac34f63, pre-register-blocking). Lesson: optimize single-thread first — it surfaced the redundant scale decode and lifts all thread counts. Kernel now ~30% of int8 peak (~320 GFLOP/s @ 1 vpdpbusd/cyc). DIAGNOSTIC (Jun 2026): temporarily skipped the per-pair _mm256_sign_epi8 → NO speedup (95→87/92→93 GFLOP/s, within noise). So the kernel is NOT sign-bound; it's execution-port-bound on the irreducible VNNI+per-block-float-rescale compute (vpdpbusd + cvt + fmadd on p0/p1/p5). CONCLUSION: the offset/zero-point trick (removes sign) WON'T help, and weight-repacking (q8_0_r8) mainly removes per-output hsum + helps loads — marginal when compute-bound, and we already beat llama. The parity-faithful Q8_0 AVX2-VNNI prefill kernel is at its practical ceiling; further single-stream gains need a lossy LUT algorithm (T-MAC) that breaks the parity gate. AMX is NOT on Arrow Lake-HX. IMPORTANT REFRAME: our gate is byte-exact GREEDY parity (token seq matches llama), NOT bit-identical logits — we already differ from llama's REPACK reduction yet match greedy. So rounding-changing kernels are allowed IF greedy holds; they just don't help here.
2. **Speculative decoding with greedy-exact verification** = LOSSLESS (accept iff draft token == target argmax → byte-identical output). Turns bandwidth-bound decode into batched compute (reuses prefill GEMM path). Start with prompt-lookup / n-gram speculation (zero training, trivially lossless); then self-speculative heads (train them — fits the educational repo). The big lossless TG lever the research failed to cover.
3. **Overlapped execution** (PP on P-cores ‖ TG on E-cores). Wall-time win for concurrent requests; single-stream numerics unchanged. Affinity primitives already shipped (set_gemma_cpus + gemma_detect_cores). See [[ch27-specialized-build-plan]].
4. **(Research-grade, park it) SIMD rANS entropy-coded Q8 weight stream** — only lossless way to cut decode bytes (int8 quants are sub-8-bit entropy). Catch: on-the-fly decode must exceed ~100 GB/s; likely net-negative unless interleaved-rANS SIMD. High effort, uncertain.
