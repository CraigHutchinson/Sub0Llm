# Sub0Llm

The current cross-project storage responsibilities and delivery gates are in the [storage stack plan](docs/STORAGE_STACK_PLAN.md). Earlier tiering proposals here are historical input; the shared plan and each library's requirements govern new integration.

A single-engine **CPU/GPU transformer language model in C++23**. The model's dimensions and its
vocabulary are *baked in at build time*: a configurator tokenizes the corpus, **auto-sizes** the model
to the corpus scale, derives the vocabulary, and emits `constexpr` config headers the engine is compiled
against. Training is data-parallel across cores (or on the CUDA device when one is present); storage is
static (BSS), not heap. There is no Python runtime.

The build is **self-configuring**: point it at a corpus and it picks a sensible model size, vocabulary,
precision, thread count and (if a GPU is present) the device backend — every choice overridable.

## Prerequisites

- **Clang** (C++23: `std::print`, `<format>`), **CMake ≥ 3.20**, **Ninja**.
- An **OpenMP** runtime (`libomp`) for the multi-threaded training path. The build *fails loudly*
  if OpenMP is missing; to build single-threaded on purpose, pass `-DSUB0_REQUIRE_OPENMP=OFF`.
- *(Optional, GPU training)* the **CUDA Toolkit** (`nvcc`) and an NVIDIA device. The CUDA backend
  is auto-detected; see [Building with the CUDA backend](#building-with-the-cuda-backend-windows)
  for the one Windows-specific setup step.

## Build

```sh
cmake --preset native                                        # configure the build (CUDA/backend detection)
cmake --build --preset native --target sub0llm-configure      # build just the configurator
out/build/native/sub0llm-configure --corpus data/tinystories.txt  # tokenize + auto-size + bake headers
cmake --build --preset native                                 # build the engine + stage tools
ctest --preset native                                          # run the unit tests
```

The `native` preset is an `-march=native` Release build. `debug` and `release` presets also exist.

`sub0llm-configure` is a plain executable with no generated inputs, so it always builds first. The engine
and stage-tool targets are unconditionally defined too, but simply fail to compile with a plain "file not
found" on the generated header until the configure step above has actually run once — there is no
CMake-orchestrated config step, and the build never regenerates config behind your back. Re-running
`sub0llm-configure` (a different corpus, an override flag) and rebuilding is how you reconfigure.

On configure it emits, into the build's `generated/` dir, **split** headers the engine compiles against
(see [Configuration](#configuration)):

- `sub0_corpus.hpp` — the model *identity* (dims, vocab, tokenizer scheme), frozen per corpus
- `sub0_system.hpp` — the *machine* (precision, thread/batch defaults, CUDA backend), per host
- `sub0_config.hpp` — a thin umbrella over both (what the engine includes)

The stage tools (`sub0llm-train/-gen/-tune`) are separate executables, built alongside `sub0llm` in the
step above. `scripts/workflow.ps1` wraps this whole sequence into one command; see
[docs/WORKFLOW_ARCHITECTURE.md](docs/WORKFLOW_ARCHITECTURE.md) for the full staged-workflow design.

### Building with the CUDA backend (Windows)

When a CUDA toolkit and device are present, the GPU training backend is built automatically. On
Windows, `nvcc` compiles `.cu` files using **MSVC `cl.exe`** as its host compiler, so `cl.exe` and the
MSVC/Windows-SDK headers/libraries must be on your environment. A plain PowerShell session does not have
these, and configure fails with `nvcc fatal : Cannot find compiler 'cl.exe' in PATH`.

Fix: run the build from a **Visual Studio developer environment** — open the *“x64 Native Tools Command
Prompt for VS”*, or initialize a shell once with `vcvars64.bat`:

```pwsh
& "C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"
```

The CPU-only build has no such requirement — only the CUDA backend needs `cl.exe`.

## Quick start

```sh
exe=out/build/native/sub0llm        # (.exe on Windows)

$exe train                          # train on the baked-in corpus into an auto-named model dir
$exe models                         # list trained models (which load into this build)
$exe gen <model.bin> "One day,"     # generate a continuation
$exe autotemp <model.bin>           # pick a sampling temperature by matching held-out text
```

`train` with **no path** creates and registers a structured model directory (see *Models* below);
`--steps 0` (default) auto-sizes the run to the corpus and stops on a validation plateau. The GPU
backend is used automatically when it was built (see *Compute backend* below).

## Configuration

**You do not set the model dimensions** — the configurator auto-sizes `d_model / n_layers / n_heads /
seq_len / vocab` from the corpus byte-scale. To re-configure, run the configurator directly (or edit the
sidecar) and rebuild — **no CMake reconfigure** is needed, because the dimensions live in the generated
headers the tool owns, not in CMake:

```sh
configure=out/build/native/sub0llm-configure
$configure --corpus data/tinystories.txt              # auto-size + emit the headers
$configure --corpus data/tinystories.txt --dmodel 256 # pin a dimension (the rest still auto-size)
cmake --build --preset native                         # recompiles against the new headers
```

A chosen size **persists** in a `<corpus>.model` sidecar (key=value), so it survives later re-runs.
The resolution precedence is **CLI flag > sidecar > auto-size**.

Auto-sizing is hardware-aware: it won't suggest a shape that can't fit the detected GPU's VRAM at
batch=1. `--size-scale 0.5` (smaller/faster/safer) or `--size-scale 2.0` (more generous) scales the
target-parameter budget without changing the underlying formula — see
[docs/CONFIGURE_ARCHITECTURE.md](docs/CONFIGURE_ARCHITECTURE.md#auto-sizing-current) for the reasoning
(scaling-law + real reference-model grounded, not hand-picked buckets).

| What | Owner | Notes |
|---|---|---|
| `d_model / n_layers / n_heads / seq_len / vocab` | configurator | auto-sized from corpus; `--dmodel`… pins; `<corpus>.model` persists |
| tokenizer (Unigram LM, JOIN scheme), precision | configurator | derived; `--join`, `--prec-gemm/--prec-act` override |
| compute backend (CPU vs GPU) | configurator | **GPU when the CUDA backend was built**, else CPU; `--compute` pins |
| whether CUDA *exists* / is built | CMake | detects the toolkit + device; `-DSUB0_COMPUTE=CPU` forces a CPU-only build |
| corpus, positional encoding | configurator | `--corpus` (required), `--pos-encoding`/`--rope-theta` |
| ternary block weights | CMake cache (`SUB0_TERNARY`) **and** configurator (`--ternary`) | CMake picks the *source files* compiled in (ternary is CPU-only for now); the configurator bakes the *flag* the engine reads — keep both in sync |

See [docs/CONFIGURE_ARCHITECTURE.md](docs/CONFIGURE_ARCHITECTURE.md) for the build-state model and
[docs/WORKFLOW_ARCHITECTURE.md](docs/WORKFLOW_ARCHITECTURE.md) for the staged user-driven workflow roadmap.

### Compute backend

CMake checks whether CUDA *exists* (toolkit + device → it builds the `nvcc` device backend); the
configurator decides whether to *use* it (`COMPUTE_MODE`). With a device present, `cmake --preset native`
builds the GPU training backend and the configurator defaults to it. Force CPU-only with
`-DSUB0_COMPUTE=CPU`, or keep the backend but run on the CPU with `sub0llm-configure --compute 0`.

### Positional encoding

`sub0llm-configure --pos-encoding` selects how position is injected (baked as `constexpr` into the
generated header): **`1` = RoPE** (default) — rotary embeddings on Q/K, relative position, no learned
table, extends to longer contexts; **`0` = ABSOLUTE** — a learned `pos_emb[SEQ_LEN, D_MODEL]` table.
`--rope-theta` (default `10000`) is RoPE's frequency base. A model is only comparable to others built
with the **same** scheme.

### Architecture options

A handful of shape/algorithm choices beyond dims and precision, each `constexpr`-baked at configure
time (except `--attn-sinks`, a generation-time flag, and `--optimizer`, a runtime training-only
flag -- see its own row below). All started CPU-only; GPU parity is landing incrementally (see the
*Backend* column). `--gated-ffn`/`--ternary` on a GPU build are rejected at configure time with a
clear error, not a silent fallback. Train and gen must agree on these: they're part of a model's
identity, like dims and vocab.

| Flag | What it does | Backend | Further reading |
|---|---|---|---|
| `--tie-embeddings 1` | LM head reuses the token embedding matrix (transposed) instead of its own matrix+bias — fewer params, no separate head weight | CPU + GPU | [Why not tie embeddings?](https://ishanjmukherjee.github.io/why-not-tie-embeddings) |
| `--qk-norm 1` | RMSNorm applied per-head to Q/K right after their projection, before RoPE (Gemma2-style) — stabilizes attention-logit magnitude | CPU + GPU | [QK norm is probably a free lunch](https://ishanjmukherjee.github.io/qk-norm) |
| `--gated-ffn 1` | SwiGLU-gated FFN (`Wgate`/`Wup`/`Wdown`, no FFN bias) instead of the plain 2-matrix GELU+bias FFN — for importing GGUF/Llama-family weights | CPU + GPU | [GLU Variants Improve Transformer](https://arxiv.org/abs/2002.05202) (the SwiGLU paper) |
| `--ternary 1` | BitNet-style ternary (`{-1,0,1}`) block weights | CPU only | [The Era of 1-bit LLMs (BitNet b1.58)](https://arxiv.org/abs/2402.17764) |
| `--pos-encoding 1` (default) | RoPE — see [above](#positional-encoding) | CPU + GPU | [RoFormer](https://arxiv.org/abs/2104.09864) |
| `--optimizer muon` (`train`) | Hidden 2D weight matrices trained with Muon (Newton-Schulz orthogonalized updates); embeddings, norms, biases, and the LM head stay on AdamW | CPU + GPU | [Muon: an optimizer for hidden layers](https://kellerjordan.github.io/posts/muon/) |
| `--attn-sinks N` (`gen`) | Once prompt+generation would exceed the trained context window, keep `N` tokens from the **start** of the sequence resident alongside the most recent tokens, instead of a plain sliding window that drops them | CPU + GPU | [Efficient Streaming LMs with Attention Sinks](https://arxiv.org/abs/2309.17453) (StreamingLLM) |

The [ishanjmukherjee.github.io](https://ishanjmukherjee.github.io/) blog (linked twice above) is a good
general companion for these kinds of small-but-load-bearing architecture decisions.

## Using a larger corpus (out-of-core)

The default corpus is small (`data/tinystories.txt`). For something big like **FineWeb-Edu**:

```sh
python scripts/get_fineweb.py --out data/fineweb_edu.txt          # ~46GB; --shards N for a slice
out/build/native/sub0llm-configure --corpus data/fineweb_edu.txt  # auto-sizes UP to a larger model
cmake --build --preset native
$exe train
```

`--corpus-pretok` (`2` = AUTO, the default) decides by scale whether to pre-tokenize the corpus to
`corpus.tok` (fast random-access training) or **tokenize on demand** from the raw text when the token
copy would not fit comfortably in RAM (estimated `corpus.tok` size vs half of physical RAM) — so a
corpus larger than memory just works; `1`/`0` force it on/off. The configurator caches its scan
(`<corpus>.words`) so re-configuring with a different vocab skips the multi-pass scan.

## Models

Each trained model is its own directory under `models/`, named for its identity:

```
models/sub0llm_<corpus>_d<D>l<L>h<H>sq<SEQ>v<VOCAB>[t][r]_<gitSHA>/
  model.bin  model.bin.ckpt  config.json  state.json
```

The "registry" is the set of `state.json` files (no separate index to drift out of sync).
`config.json` holds the architecture + recipe, `state.json` the provenance + progress; the two
partition the metadata and never restate each other.

```sh
$exe models            # list models; '*' = loadable by this build, 'x' = incompatible architecture
$exe models --prune    # delete models whose architecture this build can no longer load
```

The auto-derived path is deterministic, so re-running `train` resumes the same model from its checkpoint.

## Tooling

| Command | Purpose |
|---|---|
| `train` | train (auto-sized, plateau-stopped, crash-safe checkpoints) |
| `gen` | sample a continuation (`--temp`, `--topk`, `--n`) |
| `models [--prune]` | list / prune trained models |
| `report` | diagnose model sizing vs its corpus; per-knob retrain guidance |
| `memplan` | predicted train/gen memory footprints (breakdown + batch sweep vs VRAM) |
| `bundle --model <m>` | copy this build's exe+DLLs into a model dir; run it later without rebuilding |
| `ckpt2model --checkpoint <c> --out <m>` | extract weights from a training checkpoint into a `model.bin` gen/report can load |
| `autotemp` | pick a coherence temperature by matching held-out perplexity |
| `vocab` | print the (Unigram) vocabulary table |
| `bench` | cycle-accurate hot-path benchmark (the optimization control) |
| `tune` | auto-tune threads / batch granularity for throughput |

The pipeline stages are **also standalone executables** — `sub0llm-configure`, `sub0llm-train`,
`sub0llm-gen`, `sub0llm-tune` — so each stage can be built/run on its own (`sub0llm-train --steps 0` ≡
`sub0llm train --steps 0`). The stage tools share one runner definition with the umbrella
(`include/sub0/cli_stages.hpp`); each compiles against whatever generated header already exists, so a
missing config header is a plain compile error, not a silent auto-regenerate. `sub0llm-configure` is the
config-independent front (`--dump-vocab` also writes readable corpus/token/vocab-curve analysis files).

// IQ1_S: ggml-quants.c::dequantize_row_iq1_s, pinned cf659f240b232e15700b1721bbb43c1d973c52e9.
#pragma once
#include "sub0/quant/format.hpp"
#include "sub0/gguf_quant_tables.hpp"
#if defined(__AVX2__)
#include <immintrin.h>
#endif

namespace sub0::quant {
struct IQ1S {
    static constexpr TensorType type=TensorType::IQ1_S;
    static constexpr std::string_view name="IQ1_S";
    static constexpr BlockSpec block{256,50};
    struct Fields {
        std::uint16_t d_bits=0,qh=0;
        const std::uint8_t* qs=nullptr; // borrowed from the caller's mapped plane
    };
    [[nodiscard]] static Fields fields(const std::uint8_t* plane,std::uint64_t p) noexcept {
        const auto* blk=plane+(p/block.elems)*block.bytes;
        const auto group=(p%block.elems)/32;
        Fields f;f.qs=blk+2+4*group;
        std::memcpy(&f.d_bits,blk,2);std::memcpy(&f.qh,blk+34+2*group,2);return f;
    }
    [[nodiscard]] static int index(const Fields& f,int l) noexcept {
        return static_cast<int>(f.qs[l]|(((f.qh>>(3*l))&7)<<8));
    }
    [[nodiscard]] static std::uint64_t grid(const Fields& f,int l) noexcept {
        return gguf::IQ1S_GRID[static_cast<std::size_t>(index(f,l))];
    }
    [[nodiscard]] static float scale(const Fields& f,float d) noexcept {
        return d*static_cast<float>(2*((f.qh>>12)&7)+1);
    }
    [[nodiscard]] static float delta(const Fields& f) noexcept {
        return (f.qh&0x8000)?-gguf::IQ1S_DELTA:gguf::IQ1S_DELTA;
    }
    [[nodiscard]] static bool dequantize(std::span<const std::uint8_t> raw,std::uint64_t n,std::vector<float>& out) {
        const auto blocks=n/block.elems+(n%block.elems!=0);
        if(blocks>raw.size()/block.bytes || n>out.max_size())return false;
        out.resize(static_cast<std::size_t>(n));
        for(std::uint64_t b=0;b<blocks;++b){
            const auto base=b*block.elems;const float d=f16_to_f32(fields(raw.data(),base).d_bits);
            for(int ib=0;ib<8;++ib){
                const auto f=fields(raw.data(),base+32*ib);const float dl=scale(f,d),offset=delta(f);
                for(int l=0;l<4;++l){
                    const auto g=grid(f,l);
                    for(int j=0;j<8;++j){
                        const auto at=base+32*ib+8*l+j;if(at>=n)break;
                        const auto q=static_cast<std::int8_t>((g>>(8*j))&255);
                        out[static_cast<std::size_t>(at)]=dl*(static_cast<float>(q)+offset);
                    }
                }
            }
        }
        return true;
    }
    // Internal row core: caller validates whole blocks, input width and encoded span first.
    // Float inputs are retained. SIMD changes accumulation order, never packed weight decoding.
    template<bool Native>
    [[nodiscard]] static float dot_row(const std::uint8_t* row,const float* x,std::size_t width) noexcept {
        float sum=0;
#if defined(__AVX2__)
        __m256 accum=_mm256_setzero_ps();
#endif
        for(std::size_t b=0;b<width/block.elems;++b){
            const auto base=b*block.elems;const float d=f16_to_f32(fields(row,base).d_bits);
            for(int ib=0;ib<8;++ib){
                const auto f=fields(row,base+32*ib);const float dl=scale(f,d),offset=delta(f);
                for(int l=0;l<4;++l){
                    const auto g=grid(f,l);const auto at=base+32*ib+8*l;
#if defined(__AVX2__)
                    if constexpr(Native){
                        const auto q=_mm256_cvtepi8_epi32(_mm_cvtsi64_si128(static_cast<long long>(g)));
                        const auto w=_mm256_mul_ps(_mm256_set1_ps(dl),_mm256_add_ps(_mm256_cvtepi32_ps(q),_mm256_set1_ps(offset)));
                        accum=_mm256_add_ps(accum,_mm256_mul_ps(_mm256_loadu_ps(x+at),w));
                    } else
#endif
                    {
                        for(int j=0;j<8;++j){
                            const auto q=static_cast<std::int8_t>((g>>(8*j))&255);
                            const float w=dl*(static_cast<float>(q)+offset);sum+=x[at+j]*w;
                        }
                    }
                }
            }
        }
#if defined(__AVX2__)
        if constexpr(Native){alignas(32) float lanes[8];_mm256_store_ps(lanes,accum);for(float v:lanes)sum+=v;}
#endif
        return sum;
    }
};
static_assert(FormatModule<IQ1S>);
}


# Codified performance iteration

Sub0Llm adopts Sub0Math's shared `sub0perf` implementation and measurement methodology. This is the
entry point for new performance work. The preserved [upstream methodology](performance/Sub0Math-PERFORMANCE.md)
is pinned at `3152af9f92ff9abb3f53eaa6487392ea94ae53a1`; code, tests, runner, CMake helpers and nanobench
are vendored unchanged with hashes in `tools/perf/UPSTREAM.json` and the upstream MIT license. No
Sub0Math runtime library or network fetch is needed. `scripts/check_sub0perf_vendor.py` verifies the
snapshot; update source, hashes and documentation together in a reviewed PR rather than silently forking it.

For the local dense 27B objective and staged milestones, see [the performance campaign](performance/QWEN27B_CAMPAIGN.md).

## Everyday workflow

```sh
cmake --preset perf
cmake --build --preset perf -j2
ctest --preset perf
python3 tools/perf/bench_check.py selftest --repo .
python3 tools/perf/bench_check.py gate --repo . --level quick
```

The perf preset builds only `sub0llm-bench-denseq`, without corpus/model generation or dependencies
fetched by CPM. `SUB0_BUILD_BENCHMARKS=ON` also includes the shared rig in the normal engine build.
Defaults match upstream: a quick report after relinking, 90-second target budget, three initial
rounds, and hook installation outside CI. `SUB0MATH_PERF_ON_BUILD=ENFORCE` makes a confirmed regression
fail the after-build check; `OFF` disables that report. Hook installation chains existing hooks and
records its target/build/executable/baseline under the git common directory's `sub0perf/config.json`.
The hook/config are local; configure the perf preset in each clone to adopt them. Worktrees share
that common directory: configure one measuring build at a time and run `selftest` after changing it.
`SUB0MATH_PERF_GIT_HOOKS=OFF` disables installation (it does not remove hooks previously installed).

The pre-push gate builds the configured target, verifies the pushed HEAD/clean tracked tree, measures,
and compares with the committed host baseline and earlier local records. It skips documentation-only
updates and empty/deletion pushes. It keeps measured binaries for side-by-side reproduction. Confirmed
baseline regressions block; a regression against a local record blocks only when reproduced. The lock
serializes this repository's measuring runs; it cannot serialize other repositories' CPU work.
A bypass/deferred/noisy/environment/method-mismatch result is not a performance pass. Read the output.

Quick rotates whole groups while retaining controls and reports missing coverage. Full measures all:

```sh
python3 tools/perf/bench_check.py gate --repo . --level full
# Or select the milestone gate on a push:
SUB0MATH_PERF_LEVEL=full git push
```

Matching release/milestone tags (`v*`, `milestone/*`) also select full. Confirmation may exceed a quick
budget. The shared rig uses shuffled interleaved rounds, adjacent reference pairs, calibrated clocks,
load checks, CPU pinning, robust spread, bimodal detection, hardware counters where available, and
explicit confirmation/reproduction. Battery/saver/throttle deferrals are reported; unknown power is
labelled rather than treated as known mains. No root power-policy or affinity changes to other processes
are made. On hybrid CPUs explicitly choose a representative logical CPU with `--cpu N` for direct
`run`/`auto` commands; default pinning is the last logical CPU. Never compare methods/CPUs as equivalent.

## Correctness and the three pillars

Use [the iteration evidence template](../perf/ITERATION_TEMPLATE.md) in the linked issue/PR. Profile first,
state one falsifiable hypothesis, check independent correctness before measuring, then report correctness,
performance **and memory**. Give a mechanism three optimization passes before parking it; preserve
meaningfully different paths for later contexts. Review each increment and merge through an issue-linked PR.

The initial suite checks `denseq::project` against an independent direct packed-byte Q8_0 scalar dot at
256 and Qwen's 5120 input width, with 32 output rows, before timing. Both use the same deterministic
fixed-scale fixtures; the reference exploits the known scale and is not weakened. The groups are small,
warm-cache output-row slices, not DRAM-streamed model projections. They cover Q8_0 only; new quant
modules need corresponding representative cases. Their ratios are comparisons with that reference,
not universal abstraction-overhead budgets. A green fixture/gate is **not** 27B correctness, memory
scaling, prefill/decode throughput, or full-context quality. The earlier nine-position discrepancy was resolved by #54/PR #55: automatic reference flash
attention cast F32 K/V to F16. PR #47 records the corrected nine-position check and a complete
16-position reply/EOS check at unchanged tolerances. Future runtime changes still need their own
independent numerical/quality evidence; these samples do not establish maximum-context correctness.

For model changes, run the independent model/reference checks at unchanged tolerances and the relevant
regressions before performance interpretation. Quality uses the existing paired-perplexity contract
where supported; shorter logit checks remain smoke checks. Record real-model peak RSS separately;
sub0perf's kernel JSON does not measure RSS or certify model memory. Stage all A/B binaries/configs
before timed samples; never rebuild between them. Preserve identity hashes, prompts/token IDs, context,
workers and cache regime. Report tok/s for decode and ms/token for phase costs, every sample/spread,
and dated measured bandwidth/compute roofs for this host. Do not reuse old Windows bus/noise estimates
as Linux facts. Cold-cache runs require verified eviction; warmups in this microbenchmark are warm.

The detailed end-to-end recipes in [OPTIMIZATION_PROCESS.md](OPTIMIZATION_PROCESS.md) and
`scripts/run_perf_suite.py` remain for real models, cold/warm separation and memory pressure. Their
Windows sandbox/eviction mechanisms are not automatically portable to Linux. Keep their model-specific
correctness gates and use staged, interleaved builds; shared sub0perf supplies the new kernel iteration
rig. Do not label an ad-hoc wall-clock observation as a controlled performance claim.

## Baselines, acceptance and profiles

No Sub0Math timing baseline is reused. Before claiming a local regression check, record a full, steady
run and review the generated host baseline (never from a quick subset or contaminated measurement):

```sh
cmake --build out/build/perf --target sub0llm-bench-denseq_runs
python3 tools/perf/bench_check.py baseline \
  --results out/build/perf/perf/sub0llm-bench-denseq.samples.json \
  --baseline perf/baselines/HOST.json
```

Use the same hostname as CMake's `SUB0MATH_PERF_HOST`; re-recording requires `--reason`. A `new` row
means unbaselined. Shared default tolerances are 10% absolute time, 5% pair change, 2% instructions;
these are harness defaults, not acceptable model slowdown targets or changes to numerical tolerances.
Use stricter predeclared per-experiment criteria where relevant. `accept` requires actual measured
samples and a reason; commit its baseline change with the corresponding reviewed issue/PR. Never
accept a regression automatically to get a push through. Check raw rounds, coverage, environment and
memory/quality before accepting any timing result.

```sh
cmake --preset perf-profile -DSUB0MATH_PROFILE_FILTER=5120
cmake --build --preset perf-profile --target sub0llm-bench-denseq_perf_record
# Also available: _vtune_hotspots, _vtune_uarch, _advisor_roofline, _json, _check, _baseline
```

Profiler tools must be installed separately; unavailable counters/profilers are reported as unavailable.
`tools/perf/profile.py` and `vectorization_report.py` are the shared drivers. `.github/workflows/perf-tools.yml`
verifies vendored provenance, runs upstream synthetic gate tests, builds/checks the real fixture protocol,
and uploads full-suite three-round samples. Shared hosted CI samples are diagnostics, not a host baseline
or an enforced hardware performance verdict.

## Sub0Llm workload extensions

The implementation now lives upstream in Sub0Math's `sub0perf.workload`, reached with
`python3 tools/perf/bench_check.py workload measure|check`. The former
`tools/perf_extensions/workload.py` path is a compatibility shim. The pinned shared package remains
byte-identical to the pushed upstream commit; local code owns only workload specs and model policy.
This extension adds correctness-gated workload identities and Linux child peak-RSS budgets, which
the kernel gate cannot certify. Use the checked-in process smoke example after building the perf preset:

```sh
python3 tools/perf_extensions/workload.py measure \
  --spec perf/workloads/denseq-process.json --repo . --out out/denseq-process.json && \
python3 tools/perf_extensions/workload.py check \
  --results out/denseq-process.json --max-rss-mib 256
```

Use a new output path for each run; existing evidence is never overwritten. Choose the RSS budget before running. `measure` requires three or more samples, runs the declared
correctness command first, and refuses command failure, timeout, contention above 5%, simulated power,
battery/saver, power changes, or input/binary changes during the run. An optional priming invocation
supports `cache: warm`; `uncontrolled` makes no cache guarantee. Verified cold capture is refused.
All paths are relative to the spec file except absolute paths; executables require explicit paths.
Commands run without a shell, with bounded runtime. Specify model/config/tokenizer/prompt/oracle-script
files under `inputs` and hash their complete bytes before/after (large GGUFs incur that I/O cost outside
timing). Put workers, context length, seed, precision and implementation route in `identity`. The
chosen correctness command must implement an independent check at unchanged thresholds; exit zero
alone does not prove the chosen check is adequate. For #29, use the independent numerical gate, not
`--inspect-context` or successful token generation. A failed oracle prevents any measured invocation.

Records include all elapsed/RSS samples, output digests, measured/oracle binary SHA256, input hashes,
command arguments, adapter/spec identities, relevant threading environment, allowed CPU affinity,
source commit/dirty flag, host and power. Caller-declared environment values are stored: do not put
secrets there. Other inherited environment is not exhaustively captured; declare consequential
settings. Non-executable scripts/interpreted programs and correctness data must appear in `inputs`.
With `check --baseline PRIOR.json`, different workload/model/config/prompt hashes, oracle identity or
arguments, cache regime, adapter/timer method, affinity, environment, host and power are incompatible.
The measured binary hash may differ (it is an A/B arm); workload arguments must match. Use the same
script and input paths across arms. RSS uses each child's own Linux `wait4` high-water mark, so a
large correctness check or warmup does not contaminate measured samples. It includes process startup;
for commands with descendants it is not a sum of simultaneous process-tree memory. Invoke the engine
directly and use separate tools for aggregate service/process-tree/GPU memory.

**Elapsed time is deliberately unjudged.** It includes startup, model loading and all work inside
the invocation, sampled with a 10 ms polling bound. It is not calibrated decode/prefill/turn latency,
model tok/s or a new time-regression gate. `check` only gates the maximum observed RSS against the
explicit absolute budget and optionally validates compatibility; success is not a performance pass.
Continue using shared sub0perf for calibrated timing, confirmation and reproduction. A record from
a dirty tree remains labelled as such and is diagnostic, not a reviewed baseline.

Remaining extensions to evaluate in subsequent issues are phase-native prefill/decode metrics and
token denominators, multi-worker topology/memory-pressure metadata, and verified Linux cache control.
The generic evidence layer has been contributed in [Sub0Math PR #2](https://github.com/CraigHutchinson/Sub0Math/pull/2);
engine-specific token/context/cache policy stays here. Extend the
existing shared confirmation/acceptance path when integrating timing metrics, rather than introducing
a weaker parallel time judge. The original #50 and upstream-adoption #52 add the identity/RSS layer only. Reference correction
#55 and chat validation #47 supply separate finite numerical evidence; new performance claims still
need the appropriate runtime/quality checks and model-specific measurement methodology.


Shared workload outcomes use `sub0perf-workload-outcome-1` with `status`, `next_action` and stable
exit codes (0 recorded/within-budget, 1 over-budget, 2 refused). Helpers log to stderr; stdout contains
one JSON outcome for normal completion/refusal. Shared records use `sub0perf-workload-1`. Regenerate
older local `sub0llm-workload-1` records; they are deliberately refused as incompatible rather than
silently compared across implementations. No-clobber atomic publication requires hard-link support
on the output filesystem and refuses if unavailable. See the pinned upstream method for the complete
schema/validation contract. This removes duplicated implementation and behavioral tests; consumer
checks verify the compatibility entry point while shared tests verify the behavior.
